## Issues discovered
- `WardrobeSearchField`'s `TextFormField` needed a key derived from `value.isEmpty` (not a fixed key) so that
  externally clearing the search (the "Clear search" empty-state button) actually resets the field's own text —
  `TextFormField.initialValue` is only honored once, on first build, otherwise. Noted in a code comment.
- The `AnalyzingView`/`GeneratingView`-style screen (repeating spinner) makes `tester.pumpAndSettle()` flush the
  full 1150 ms delay in tests (the spinner keeps requesting frames, so `pumpAndSettle` keeps advancing the fake
  clock until the real `Future.delayed` fires and the repeating animation goes away). Tests that need to observe
  the screen *before* the delay elapses use a plain `tester.tap()` + `tester.pump()`/`pump(duration)` instead of
  `tapText` (which calls `pumpAndSettle`). This is a pre-existing gotcha (the same applies to F03/F04's
  `GeneratingView`), just calling it out since it was non-obvious while writing new tests against it.
- `AppToast` keeps static `OverlayEntry`/`Timer` state across the whole test file; any test that triggers a toast
  must `await drainToast(tester)` before the test ends (existing convention, confirmed from
  `stylist_screens_test.dart`/`auth_screens_test.dart`) or the *next* test can fail with a stale-overlay
  exception. All toast-triggering tests here drain.
- `app.dart` now provides `WardrobeBrowseCubit` and `ImportCubit` at the root — see the note under Completed.
  This is outside `lib/features/wardrobe/`, flagging per the "flag anything outside your layer" instruction even
  though I judge it consistent with the existing `StylistCubit` precedent.
- Section-header item counts (`'<n> items'`) are computed as category+search filtered count always (matching
  §11 assertions), not the prototype's literal `app.js` markup which (on a plain `render()`, outside the search
  `oninput` handler) would show the *total* unfiltered count. The assertions are the source of correctness per
  the contract, so I implemented the assertion behavior, not the apparent prototype quirk; flagging for the
  parity pass in case the live build should instead match the prototype bug.
