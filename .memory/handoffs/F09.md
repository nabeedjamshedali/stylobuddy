## Issues discovered
- Reusing one `tester` across multiple `pumpApp(...)` calls in the same `testWidgets` body does
  **not** give a fresh `PlannerCubit`/`OutfitsCubit`: `tester.pumpWidget` diffs the new
  `StyloBuddyApp(router: ...)` against the old one (same widget type, same slot) and preserves the
  `BlocProvider` elements/state, only swapping the `router` — so any Cubit mutation from the first
  `pumpApp` call is still visible after a second `pumpApp` call in the same test. This bit F09-A06
  (next-month vs. previous-month) when both scenarios lived in one test; split into two separate
  `testWidgets` to get genuinely isolated state. Flagging since this pre-existing harness quirk
  (`test/features/support/f02_harness.dart`) will bite any other feature that calls `pumpApp` twice
  in one test after mutating a root-provided Cubit.
- `CalendarPlanCard`'s `Row(crossAxisAlignment: stretch)` inside a `Container` with only a
  `minHeight` constraint threw "BoxConstraints forces an infinite height" — fixed with an
  `IntrinsicHeight` wrapper. Noted in case other features hit the same pattern when mixing
  `CrossAxisAlignment.stretch` with an unbounded-height parent.
- Both `CalendarSummaryRow` and `CalendarSecondaryActions` overflowed `RenderFlex` at 390px width
  with a plain `Row(mainAxisAlignment: spaceBetween)` — wrapped the text children in `Flexible`.
- The screen-head back chevron (`‹`) and the calendar's month-nav previous button also render `‹`,
  so `find.text('‹')` is ambiguous on `/calendar`; tests disambiguate with `.first` (screen head,
  first in the widget tree) / `.last` (month nav).
- Driving the real `showDatePicker` dialog from a widget test (for F09-A13) works by tapping the
  dialog's first `IconButton` (switches to text-entry mode), then `enterText` on the resulting
  `TextField` with a `MM/dd/yyyy` string, then tapping `OK` — documented as `typeDatePickerDate()` in
  `calendar_screens_test.dart` for reuse if another feature needs the same pattern.
