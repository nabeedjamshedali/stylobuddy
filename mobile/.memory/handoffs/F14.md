## Issues discovered
- **Real regression caught and fixed, not hidden.** Wiring `lib/app.dart`'s default
  `uidStream ?? uidChanges()` initially broke all 14 `pumpApp`-based test files plus the smoke
  test, because `FirebaseAuth.instance` throws *synchronously* when `Firebase.initializeApp()`
  was never called (which is true of every current widget test). Fixed by making `uidChanges()`
  catch that synchronous failure too (ADR-003), confirmed via a full `flutter test` run showing
  413/413 pass with zero existing assertions altered. Flagging this prominently because the
  implementer-contract's "stop and report" rule for assertion-breaking changes almost applied
  here — I judged this a legitimate robustness fix matching F14's own degradation spec (§10:
  "uidChanges() never throws into its listener") rather than a design error, but a reviewer
  should double check that reasoning.
- **`fake_cloud_firestore`'s `runTransaction` is not atomic.** It just calls the handler once
  against a dummy `Transaction`; it does not simulate Firestore's real retry-on-conflict
  behavior. `FirestoreService.runBootstrapIfNeeded` therefore has its own app-level per-uid lock
  so A18 (two concurrent calls, one `seedWriter` invocation) holds against both the fake and real
  Firestore. Documented in ADR-003; later tasks writing their own transactional methods should be
  aware this fake does not give them free concurrency correctness.
- No `firestore.rules` exists yet in the repo (confirmed not touched, matches Task 9's ownership)
  — F14's `runBootstrapIfNeeded`/`subcollection` helpers are unauthenticated-by-construction in
  tests (fake Firestore has no rules), which is fine for this task but means Task 9 is the first
  real enforcement point.

## Fix round (post-review)

Reviewer found 2 Important + 9 Minor issues. All fixed; see
`.superpowers/sdd/2026-10-19-backend-wiring/task-1-report.md` for the full fix report (per-finding
detail, TDD evidence, commands/output). Summary:

- **Important #1 (uid-keyed rebuild didn't tear down routes):** `lib/app.dart`'s `StyloBuddyApp`
  converted to a `StatefulWidget`; the `GoRouter` (when no `router:` override is passed) now lives
  inside a new `_RoutedMaterialApp` *child* of the uid-keyed `MultiBlocProvider`, built fresh in
  its own `initState` — so a uid change disposes the whole navigation tree, not just the
  providers. Added a regression test (`F14_A05_regression` in `test/app_backend_wiring_test.dart`)
  that navigates to `/manual-preview` (whose view caches a `BuilderCubit` in `initState`), flips
  the uid, and asserts the route is gone and the cached cubit is closed — proven RED before the
  fix (reparented route found, stale cubit not torn down) and GREEN after. Also strengthened the
  existing `F14_A05` test to assert every pre-transition cubit `.isClosed` is `true`, not just that
  a new instance exists.
  - Side-effect discovered and fixed: naively building the router in `build()`/`initState` without
    also handling `didUpdateWidget` broke ~33 existing tests that call `pumpWidget(StyloBuddyApp(router: ...))`
    more than once on the same `tester` with a *different* router instance each time (e.g.
    `F02_A25`'s 3-iteration loop) — Flutter reconciles that as the same root `Element`
    (`didUpdateWidget`, not a fresh `initState`), so the stale cached router/stream would have won.
    Added `didUpdateWidget` overrides on both `_StyloBuddyAppState` and `_RoutedMaterialAppState`
    that adopt a new non-null override when it changes identity — a no-op in production, since
    production never passes an override.
- **Important #2 (bootstrap contract overclaim):** `seedWriter` may run more than once on
  contention; only the **commit** is at-most-once. Corrected the docstring in
  `firestore_service.dart` and `docs/features/F14-backend-foundation.md` §5/§9, and added a note
  that a transaction fails outright while offline (callers must handle that failure path).
- **Minor #1:** `auth_session.dart`'s `catch (_)` narrowed to `catch (error)` with a `debugPrint`
  in `kDebugMode` so an unexpected synchronous failure isn't silently swallowed.
- **Minor #2:** F14 §12's edge-case bullet rewritten to describe the actual mechanism (the
  synchronous guest-mode guard inside `uidChanges()`), not the old "tests inject a fake stream"
  assumption, and lists the 14+ real harness call sites that rely on it.
- **Minor #3:** Added a literal `test('F14_A07 ...')` widget test pumping `StyloBuddyApp()` with
  no `uidStream` override, asserting guest/SeedData renders.
- **Minor #4:** Retitled the A12 test to be honest about what it proves (a caller that follows the
  convention round-trips correctly) and added `F14_A12_edge` proving `subcollection()` does
  *not* reject/correct a caller that omits the id field — the convention is a caller contract,
  not an enforced one.
- **Minor #5:** `07-security.md` §3 now says "(identical in-memory construction until Tasks 2-7
  land their own repositories)".
- **Minor #6:** `StyloBuddyApp` is now a `StatefulWidget`; `uidChanges()` is subscribed to once in
  `initState`, not on every `build()`.
- **Minor #7:** `_bootstrapLocks` keyed by `'${identityHashCode(_firestore)}/$uid'` (not
  `.app.name` — `fake_cloud_firestore`'s double throws `NoSuchMethodError` on `.app`, confirmed by
  a throwaway check before choosing `identityHashCode`), and each entry is pruned once its attempt
  settles. Added `FirestoreService.bootstrapLockCount` (`@visibleForTesting`) and a test proving
  the map returns to its prior size after an attempt completes, plus a test proving two
  `FirestoreService` instances backed by different doubles don't share a lock for the same uid.
