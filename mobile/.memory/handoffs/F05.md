## Issues discovered
- The task-5-brief.md (written before F03 landed) said "View outfits" should
  call `StylistCubit.generateAutomatic(occasion: 'Everyday')` and, until a
  hypothetical "Task 6" landed, navigate to `AppRoutes.occasion` instead.
  That API/sequencing never matches the real `StylistCubit` (which exposes
  `setOccasion(String)` and a no-arg `generateAutomatic()`, already built by
  F03/task 4). The dispatch message's ruling superseded the brief here and
  is what was implemented: `setOccasion('Everyday')` then `generateAutomatic()`
  then `push(AppRoutes.generating)` — identical to the pattern
  `StylingOptionsView` already uses for its "Generate 3 looks ✧" button.
  Flagging this per the contract ("if the two conflict, the feature document
  / dispatch wins — note it in your report").
- `/import` and `/clothing` (used by "Add Item" and the first recent tile)
  are still `GenericPreviewView` placeholders owned by the wardrobe feature
  (not yet built) — navigation to them is correct and tested (via a
  purpose-built stub router in `F05_A09` to assert the exact `id` query
  param, since the real screen doesn't render it yet). No action needed from
  this layer; just noting for whichever task builds wardrobe/import so it
  knows Home already pushes `AppRoutes.clothing(id)` / `AppRoutes.import`.
- No Android/iOS-specific code added (icons are inline SVG + bundled
  fonts/images already used elsewhere); nothing platform-specific to flag.
