## Issues discovered
- `SlLookCard`'s `.sl-look-foot` row (`'<n> times worn'` / `'View look →'`) overflowed `RenderFlex`
  under `GridView`'s fixed `childAspectRatio` at 390px width — the two-line name box plus the foot
  row needed slightly more height than the aspect ratio allowed, and the foot row itself needed one
  `Flexible`+ellipsis to tolerate wider text metrics in the test environment. Fixed by replacing the
  `GridView.builder`/`childAspectRatio` gallery with a manual `IntrinsicHeight` row-of-two layout
  (no fixed aspect ratio to overflow against) and wrapping the muted foot label in `Flexible`.
- `RichText` directly (rather than `Text.rich`) is invisible to `find.text()` in widget tests (the
  finder only matches `Text`/`EditableText`, not raw `RichText`) — switched the 'My Looks.' two-tone
  heading to `Text.rich(TextSpan(...))`, matching the existing convention in
  `lib/features/matching/widgets/mm_step_heading.dart`.
- `OutfitsCubit.logWear`'s default clock is real `DateTime.now()` (no fixed seed date), so
  wear-detail/timeline date assertions can't assume `'October 15, 2026'` for freshly-logged events —
  only the calendar's seeded plan is pinned to that date. Tests compute the expected
  `DateFormat('EEEE, MMMM d')`/`'MMMM d, y'` string from the actual logged timestamp instead.
- Confirmed by reading existing root providers in `lib/app.dart`: `PlannerCubit` and `BuilderCubit`
  are both already app-root-provided (from F09/F07), so `saved_detail_view.dart` only needed to
  `context.read` them directly — no new wiring in `lib/app.dart`, which was left untouched per the
  ruling.
