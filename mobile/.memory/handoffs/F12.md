## Issues discovered
- `SavedViewCubit`'s tab state is not reachable from outside `lib/features/saved/**` (see Not
  completed above) — this will recur for any other feature whose "jump to saved with a specific
  tab" link needs real parity (e.g. if a future feature also needs this).
- Dart's `List.sort` stability is not guaranteed by the language spec, so ties in `cats`/
  `occasions`/`top` are broken explicitly by original index inside `InsightStats` rather than
  relying on sort stability — this matters because the seed has exact count ties (Shirts/
  Accessories both 5; Pants/Shoes both 4; Dresses/Outerwear both 2) and wear ties (four items
  tied at 4 wears for `top`).
- Flutter widget tests without real font metrics can overflow `Row`s that fit fine with the
  real bundled fonts (two `Row`s in `InSectionHead` and `InWearActivityCard` initially
  overflowed in tests only). Fixed by wrapping the flexible text in `Expanded`/ellipsis, which
  is also simply more robust than a fixed-width `Row`.
- Several assertions require numbers that coincidentally repeat elsewhere on the same screen
  (donut centre count == WARDROBE stat count; EVER WORN stat == the worn count shown again in
  the wear-activity card; category labels appear in both the mix legend and the bars card). Tests
  disambiguate with `find.descendant` scoped to the specific widget type, or `findsExactly(2)`
  where prototype intentionally repeats the number/label in two places.
